# Tool reference

_Generated by `scripts/gen_tool_reference.py` from the live registry - do not edit by hand._

**33 tools.** Every call passes through the executor (`agent/tools/base.py`): Pydantic argument validation, policy pre-checks, human-confirmation gating for operate/mutate tools, a hard timeout, error classification (`ok | error | unavailable | timeout | invalid_request | denied | requires_confirmation`) and a structured `tool_call` log record. `?` marks optional arguments.

## DVC - data management (7 tools)

| Tool | Permission | Arguments | Purpose |
|---|---|---|---|
| `dvc_list_tracked_datasets` | read - runs immediately | _none_ | List every dataset / artefact tracked by DVC (.dvc pointer files and dvc.lock pipeline outputs) with md5, size and the remote storage configuration. |
| `dvc_get_dataset_version` | read - runs immediately | `path?`: string (default `data/raw/credit_risk.csv`) | Get the CURRENT version of a dataset: tracked md5, git commit, the dataset version tag it maps to, and whether the workspace copy matches what DVC tracks. |
| `dvc_list_dataset_versions` | read - runs immediately | `path?`: string (default `data/raw/credit_risk.csv`)<br>`limit?`: integer (1..100; default `20`) | List the version history of a DVC-tracked dataset: every git commit that changed it, its md5, date and version tag. |
| `dvc_compare_versions` | read - runs immediately | `rev_a`: string<br>`rev_b?`: string (default `HEAD`)<br>`path?`: string (default `data/raw/credit_risk.csv`) | Compare two versions of a dataset (tags like data-v1.0, version names like v1.0, or commits): md5 change, row counts, class balance, schema changes and per-feature drift (PSI). |
| `dvc_check_data_status` | read - runs immediately | _none_ | Detect whether DVC-tracked data or pipeline stages have changed (`dvc status`): modified workspace data, stale pipeline outputs, missing cache. |
| `dvc_resolve_run_dataset` | read - runs immediately | `run_id`: string | Provenance: given an MLflow run id, find the exact dataset version (DVC md5 -> git commit -> version tag) that the run was trained on, from tags recorded at training time. |
| `dvc_reproduce_dataset` | read - runs immediately | `version`: string<br>`path?`: string (default `data/raw/credit_risk.csv`)<br>`verify?`: boolean (default `True`) | Explain AND verify how to reproduce a previous dataset version: materialises that version from the DVC cache/remote into a scratch directory (never touches the working tree), verifies its md5, and returns the exact commands an engineer should run. |

## Policy limits (from `config/agent_policy.yaml`)

- Kubernetes namespaces (read and write): `['mlops-agent']`; mutable deployments: `['inference-api']`; replica bounds: {'min_replicas': 1, 'max_replicas': 5}
- Triggerable DAGs: `['ml_training_pipeline']`; allowed conf keys: `['inject_failure', 'model_type', 'reason']`
- DVC sub-commands: `['status', 'diff', 'data', 'get', 'list', 'version', 'params', 'metrics', 'doctor']`; git sub-commands: `['log', 'rev-parse', 'describe', 'show', 'tag', 'status', 'diff', 'cat-file', 'ls-files']`
- Confirmations expire after 600 s and are single-use, bound to the session and to a SHA-256 fingerprint of (tool, arguments).
